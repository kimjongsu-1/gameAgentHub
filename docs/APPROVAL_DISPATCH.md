# 승인과 채팅 전달 큐

## 안전 게이트

`게임 개발 디자인` 결과가 바로 Unity로 이동하지 않도록 두 개의 독립 조건을 강제한다.

```text
Sprite QA PASS + 사용자 APPROVED = 게임개발 전달 큐 생성
```

기본 디자인 승인, QA 미실행 에셋, `FIXABLE`, `REDRAW`, 재작업, 거절 상태는 게임개발 큐를 만들지 않는다.

## 승인 UI

- 승인 요청에 등록된 PNG, JPG, GIF, WebP를 최대 5개까지 표시
- 승인, 재작업, 거절 제공
- 이미 결정된 승인 ID의 중복 처리는 HTTP 409로 차단
- 미리보기 파일은 프로젝트 워크스페이스 안에서만 제공
- 임의 경로 접근과 허용되지 않은 파일 확장자는 차단

## 전달 상태

- `PENDING`: 승인 후 전송 대기
- `CLAIMED`: 한 워커가 선점함
- `SENT`: 대상 채팅 전달 완료
- `FAILED`: 전달 실패, 오류 요약 저장

전달 성공 시 새 Unity 통합 작업은 `RUNNING`이 된다. 실패 시 원본 승인과 에셋은 훼손하지 않으며 큐 기록으로 남긴다.

## 자동화 경계

FastAPI 서버는 Codex 내부 채팅 권한을 직접 보유하지 않는다. 따라서 서버는 안전한 전달 큐를 만들고, 현재 오케스트레이터에 연결된 주기적 워커가 Codex 채팅 전송을 담당한다.

주기적 워커는 현재 활성화되어 5분 간격으로 동작한다. 외부 이미지 또는 LLM API를 호출하지 않고 로컬 큐와 기존 Codex 채팅만 사용한다. 전달할 항목이 없으면 상태를 변경하지 않고 종료한다.
